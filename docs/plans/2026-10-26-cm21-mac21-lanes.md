## Gotchas learned

- **zsh is not bash.** `$VAR:r` and `$VAR:s` are zsh history modifiers, so `"$C:refs/heads/x"` silently mangles the ref. Always brace: `"${C}:refs/heads/x"`. zsh also does not word-split unquoted `$VAR`, so a space-separated list in one variable is one argument; use an array.
- **pgrep waiters can match themselves.** A `while pgrep -f "<pattern>"` waiter whose own command line contains the pattern waits forever. Two background helpers sat for over an hour this way. Fix: bracket one character (`[c]odex`) or match on a PID, and run every waiter under the watchdog.
- **Squash-merged stacked PRs need a rebuild.** After the lower PR squash-merges, the upper branch still carries the original commits and conflicts with its own squashed copy. Rebuild the upper branch from the new base and cherry-pick only its own commits (full ids, then assert each pick landed).
- **Codex-rebuilt node_modules broke a loopback test.** After Codex rebuilt `node_modules`, a loopback test failed for reasons unrelated to the change. Treat a local red after a Codex reinstall as an environment suspect first: reinstall outside the sandbox and rerun before chasing it in code.
- **Semantic merge clash (renamed parity test).** A merge from base was textually clean, but base had renamed a parity test the branch relied on. No conflict showed; only the full suite caught it. After every merge from base, rerun the full suite, not only the touched specs.
- **Sentinel caught two viasr privacy and coverage gaps before shipping.** (1) Shared reflections between two people could read one person's crisis chat; fixed in 9c3e28a6 so every shared AI text skips crisis chats. (2) The circle weekly card was blocked as a whole card in a crisis week instead of only the crisis content, so it would never arrive; the viasr side needs a small fix before #1482 can merge.
