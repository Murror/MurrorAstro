# Murror cross-platform isolation policy

Last updated: 2026-08-04

## Purpose

Keep Codex cross-platform parity work independent from Claude's active iOS staging work. Murror includes iOS, Android, and web. There is no Murror macOS app. Uni is a separate product and is never an acceptable checkout for this work.

## Ownership lanes

| Lane | Path | Owner while iOS staging is active | Rule |
|---|---|---|---|
| Protected iOS | `/Users/astro/Projects/murror-transfer/Murror/MurrorMobile` | Claude / Astro | Do not edit, clean, install, regenerate, switch branches, build, or archive from this checkout. |
| Web integration | `/Users/astro/Projects/murror-transfer/Murror/murror-platform-worktrees/codex-web-parity-integration-20260804` | Codex | Current-`origin/dev` web source, generated contract, tests, and workflow guards only. No deploy or flag mutation. |

| API contract integration | `/Users/astro/Projects/murror-transfer/Murror/murror-api-worktrees/codex-openapi-provenance-20260804` | Codex | Deterministic response typing, schema export, and contract tests only. No migration, staging write, or deploy. |
| Legacy parity lanes | `murror-web-parity-codex`, `codex-android-staging-parity`, `codex-openapi-contract`, and `codex-together-contract` | Preserved / read-only | Do not edit, clean, merge, or treat legacy-only source as current integration evidence. |

The existing Murror root and every other dirty checkout are user-owned unless explicitly assigned. They are not cleanup targets.

## Required preflight

Use the product guard first, then the stricter lane guard before any cross-platform command:

```sh
zsh /Users/astro/Projects/murror-transfer/verify-murror-workspace.sh
zsh /Users/astro/Projects/murror-transfer/verify-murror-cross-platform-workspace.sh /absolute/path/to/the/approved/worktree
```

The second guard accepts only the three current Codex integration worktrees above. It explicitly rejects the four legacy parity lanes, the canonical iOS checkout, the canonical API checkout, the Murror container root, both Uni locations, and every unlisted worktree.

## No-conflict rules

1. Never share a working directory with Claude. Worktree separation is the boundary, not a naming convention.
2. Never run `git clean`, `git reset`, `git checkout`, `git stash`, branch switching, Xcode project generation, CocoaPods install, or iOS archive commands in the protected iOS checkout.
3. Do not copy generated files, dependency directories, Pods, build output, `.xcconfig` files, or Xcode project files between lanes.
4. Cross-platform diffs may touch web, Android, API contract, CI contract checks, and parity documentation only. Any iOS path is an automatic stop condition.
5. Do not merge, deploy, or change staging flags while Claude's iOS staging repair is active. Prepare reviewable commits or a handoff only after the iOS owner confirms the lane is ready.
6. Record a status snapshot before and after material work. The protected iOS snapshot must be unchanged by Codex.

## Cleanup policy

Cleanup is evidence-first and scoped:

1. Inventory exact task-owned artifacts with `git status`, focused `find`, and `du`. Do not scan-and-delete broad caches.
2. Finish all required local validation before cleanup. Confirm every candidate is ignored and confined to one approved isolated worktree.
3. Reproducible dependency trees and build outputs installed or generated by this task may be removed by exact path after validation. Move ambiguous or non-reproducible artifacts to a dated folder under `/Users/astro/.Trash/` with a manifest instead.

Current cleanup boundary:

- The iOS `node_modules`, `ios/Pods`, `ios/build`, modified Xcode/config files, and nested iOS worktree directories are protected and remain in place.
- All dependencies and build artifacts in legacy parity lanes are protected regardless of their ignored status.
- In the three current integration lanes, only exact ignored task-owned paths recorded in the current cleanup inventory may be removed. Tracked contract artifacts, lockfiles, sources, and workflow files always remain.
- Shared package-manager caches outside an approved worktree are never cleanup targets.

After cleanup, rerun the product guard, Git status, artifact-presence checks, and disk-space measurement. A clean Git tree proves source preservation; it does not replace the earlier test evidence.

## Handoff protocol

When iOS staging is ready for cross-platform integration, the iOS owner shares:

- the exact branch or commit to consume,
- the target staging environment,
- any shared API/schema changes that need review,
- the validation evidence and remaining device or external gates.

Codex then reviews the cross-platform diff against that immutable reference. No active checkout is repurposed, and no user-owned dirty files are reconciled implicitly.
