## The paywall footer, five failed attempts and the actual cause

The sticky footer was a plain **flex sibling** of its `ScrollView`. In a flex
column that means it occupied its own space, so the scroll view ended where the
footer began and **page content never passed behind it**. Its backdrop was bare
screen background, and a fade over nothing is indistinguishable from a solid fill.

Builds 353 (gradient-masked BlurView), 399 (retuned mask stops), 413 (feather +
scrim + inset blur) and 415/416 (gradient 0.92 -> 0.72 -> 0.70) all tuned colour
on a layer with nothing behind it.

Measurement that should have caught it sooner: the whole ramp moved luminance by
**~5 units out of 255**. That was read as "black gradient over near-black content"
when the real answer was that there was no content there.

Fix: `position: absolute` so the footer overlays the scroll content, plus the
app's card glass recipe (`blurAmount 5`) behind the existing gradient.

**Blur and fade must stay two layers on iOS.** A `BlurView` is a
`UIVisualEffectView`, which ignores a `CALayer` mask, so it cannot be feathered
and has a hard edge wherever it starts (`locked-card.tsx:34`). The gradient does
the fade; the blur does the texture.

### The self-defeating first attempt

Padding the `ScrollView` by the FULL footer height cleared the content completely,
so at maximum scroll the glass rested over flat base and looked exactly as solid
as before. The padding that stops content being trapped is the same padding that
guarantees emptiness behind the glass. Now `FOOTER_SCROLL_CLEARANCE = 0.45`, so
real content rests behind it. The last element there is a non-interactive
`GradientText`, so nothing tappable is veiled.

## The adversarial review earned its keep

Ran before the archive per `CONVENTIONS.md` §8. Found three blockers plus two of
my own overstatements.

### Blocker, sign-out footgun

Rendering `use-different-account` unconditionally newly exposed **immediate
logout, no confirmation, no undo** on every in-app soft-paywall gate
(`open-upgrade.ts:52`) and the upgrade sheet (`upgrade-sheet-host.tsx:268`). Those
users are signed in mid-session and the caption sits inside the iOS swipe-up zone.
Production sends no confirmation emails, so a user who cannot recall their
password is materially stuck.

Fixed with a confirm dialog reusing the **settings logout dialog's existing copy
and button shape**, so no locale keys were added. A dedicated test locks the gate,
because the other tests in that describe invoke the confirm button directly and
would stay green if the dialog were deleted.

The review also **cleared the A/B worry**: the old spec name
"byte-identical control" is not an experiment arm. `onboardingVariant` is only ever
`'v2'` at every call site, so nothing was measured and nothing broke.

### Blocker, the "one derivation" claim was false

Darkening only the shared component left **15 hand-rolled copies** of
`['#000000', '#323245']` behind. Nine were full-screen backdrops, so the change
manufactured new same-flow steps, e.g. submitting the mental-health test darkened
the background ~2.4x between quiz and result where before both matched.
`home-screen.tsx:525` was also latent for prod, where the orbital gate is off.

Aligned the nine backdrops by value. The five sheet and card fills are left
deliberately, since those are meant to read as distinct surfaces.

### Also fixed from the review

`reducedTransparencyFallbackColor` was `0.90`, i.e. a near-opaque slab for Reduce
Transparency users, which is the exact complaint. Now `0.55`. Restored two
hairline side-colour assertions an earlier spec rewrite dropped. Corrected
comments that still named the old colour or claimed there was no blur.

## Memo last-word flicker, two wrong theories then one that fits

**Theory 1 (from the handoff): the completion callback never fires.** Wrong. It
fires, and `AnimatedFadeWord`'s effect deps are stable.

**Theory 2 (mine): the `Animated.Text` -> `Text` element-type swap on settle.**
Also wrong, and Astro's observation is what killed it: the rainbow renderer used
by AI chat and the founder letter performs the **same swap** and does not flicker.

**Theory 3, which fits.** The screen passed an inline arrow to `onComplete`.
`FadeMarkdownText` carries `onComplete` in the deps of the effect owning both the
reveal ticker and the completion timer, so a fresh identity every render tore that
effect down and restarted its `fadeDurationMs` timer repeatedly. That branch only
runs once `visibleCount >= wordCount`, in other words once the **last word** is
already on screen.

It also explains the uniqueness: `personal-note-letter-screen.tsx:331` is the only
caller passing `revealStyle="fade"` (so the only one reaching that effect) AND the
only one passing an unmemoized callback. Handlers are now cached per paragraph
index; `setActiveIndex` uses its functional form so a cached closure cannot go
stale.

**Still proven by reading. Neither screen has a spec.**

## MTC card overlap, still open, no seventh fix

Did not reproduce across four simulator configurations (3 journal cards at rest,
paging 1-2-3, hard fling past the last card, 3 `moment` cards with 3-photo fans).
A temporary harness injected mocks at the `usePinnedFeed()` boundary, leaving
`pinned-compact-feed-card.tsx` byte-identical, and was fully removed before
committing.

Eliminated with proof: the patched carousel opacity hunk (only runs for
`mode="horizontal-stack"`, this rail passes no `mode`), `Dimensions` at module
import (build-414 telemetry says `screen_width 402`), and the
`Number.MAX_SAFE_INTEGER` parked-sentinel theory I raised and then **downgraded
myself**, because parking only ever targets far, already-offscreen indices.

🚨 The build-414 geometry telemetry is unreliable: `reportGeometryOnce`
(`pinned-compact-feed-card.tsx:128`) returns early when `measuredSlotWidth <= 0`,
so it **structurally cannot report a bad frame**. Its in-code conclusion that the
geometry "IS ALREADY CORRECT" is not settled fact.

**Recommendation:** a latching diagnostic recording the real max per-item
`animationValue` and measured face/stride, reported when the overlap happens on
Astro's device.

## Gotchas worth remembering

- **The upload was NOT impossible.** I twice told Astro it was blocked on a
  missing distribution certificate. The answer was in
  `docs/runbooks/ios-build.md` all along: pass
  `-authenticationKeyPath` / `-authenticationKeyID` /
  `-authenticationKeyIssuerID`. The API key IS the account, and with
  `-allowProvisioningUpdates` xcodebuild fetches the certificate itself. "No
  Accounts" meant not authenticating, not a missing cert. **Read the runbook
  before declaring a blocker.**
- **`ios-next-build.sh` MUTATES.** I ran it as a read-only ASC query and it wrote
  419 into the tree. Reverted, no harm, but never use it as a status probe.
- **Verify the screen before sampling pixels.** Reported numbers from the wrong
  screen three times. See `feedback_verify_screen_before_sampling_pixels`.
- **`git checkout -- ios/Podfile.lock` desyncs the pod sandbox** against
  `Pods/Manifest.lock` and fails the archive. Re-run `pod install` with
  `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8`.
- zsh does **not** word-split unquoted variables, so `for f in $FILES` with a
  newline-separated string passes one giant filename. List files inline.
- `hermes.framework` dSYM is missing from the archive, so Hermes frames in crash
  reports will not symbolicate. Non-blocking, pre-existing.
